# PRD: 영단어 플래시카드 웹앱 — 1단계 (MVP)

## 1. 개요

브라우저에서 바로 쓰는 1인용 영단어 플래시카드 웹앱의 1단계(MVP)에 대한 제품 요구사항 문서다. 외부 서버나 로그인 없이, 단일 사용자가 로컬 브라우저에서 단어를 등록하고 카드를 넘기며 암기 여부를 표시하는 최소 기능을 제공한다.

- **상태**: 완료 (구현·검증 완료)
- **구현 위치**: `index.html`, `style.css`, `app.js` (프로젝트 루트)
- **범위**: 전체 3단계 중 1단계

## 2. 목표

- 설치·빌드 과정 없이 `index.html`을 열기만 하면 바로 쓸 수 있는 영단어 카드 학습 도구를 제공한다.
- 카드 앞/뒤 뒤집기, 다음 카드 이동, 암기 완료 체크라는 가장 기본적인 학습 루프를 완성한다.
- 단어를 직접 추가할 수 있게 하고, 추가한 내용과 학습 진행 상태가 새로고침 후에도 유지되게 한다.
- 2~3단계에서 기능을 덧붙이기 쉽도록 데이터 모델과 코드 구조(상태/저장/렌더링/동작 분리)를 먼저 잡아둔다.

## 3. 목표가 아닌 것 (Out of scope)

- 서버 연동, 계정/로그인, 기기 간 동기화
- "암기 전만 보기" 등 필터 기능의 실제 동작 (데이터 모델에 `filter` 필드만 미리 준비)
- 단어 수정·삭제, 카드 순서 변경, 폴더/카테고리 분류
- 발음, 예문, 이미지 등 단어 부가 정보
- 통계, 복습 주기(SRS) 등 학습 알고리즘
- 다국어 UI (한국어 고정)

이 항목들은 2단계 또는 3단계 PRD에서 다룬다.

## 4. 사용자 및 사용 시나리오

- **대상 사용자**: 영단어를 혼자 암기하려는 1인 사용자(한국어 사용자), 별도 설치 없이 바로 쓰고 싶은 사람.
- **핵심 시나리오**: 앱을 열면 카드가 바로 보인다 → 카드를 눌러 뜻을 확인한다 → 암기했으면 완료 체크를 한다 → 다음 카드로 넘어간다 → 필요하면 단어 관리 화면에서 새 단어를 추가한다 → 탭을 닫았다가 다시 열어도 진행 상황이 그대로 남아있다.

## 5. 기술 조건

- 순수 HTML/CSS/JavaScript, 프레임워크·빌드 도구 없음. 파일은 `index.html`, `style.css`, `app.js` 3개로 구성.
- 브라우저에서 파일을 직접 열거나(`file://`), GitHub Pages 같은 정적 호스팅으로 실행 가능해야 함.
- 외부 라이브러리, 분석 스크립트, 외부 네트워크 요청 없음(완전 오프라인 동작).
- UI 문구는 모두 한국어.

## 6. 화면 구성

화면은 2개이며, 전환은 섹션 표시/숨김(`hidden` 속성)으로 처리한다. 앱 시작 시 항상 학습 화면이 먼저 보인다.

### 6.1 학습 화면
- 헤더: 앱 이름("영단어 카드"), "단어 관리" 버튼
- 카드 영역: 플래시카드, 위치 표시("3 / 20")
- 하단 고정 컨트롤: "암기 완료" 토글 버튼, "다음" 버튼(가장 크게)

### 6.2 단어 관리 화면
- "학습으로 돌아가기" 버튼
- 영단어·뜻 입력 폼 + "추가" 버튼
- 전체 단어 목록(영단어, 뜻, 완료 여부)

화면 전환 시 상태는 보존된다. 즉, 단어 관리 화면에 다녀와도 학습 화면은 보고 있던 카드를 그대로 유지한다.

## 7. 기능 요구사항

### F1. 카드 표시·뒤집기
- 앞면에는 영단어만 크게, 뒷면에는 뜻(영단어는 작게 함께 표시)을 보여준다.
- 카드를 클릭·탭하면 앞↔뒤가 전환되며, 0.3~0.5초의 3D 회전 애니메이션이 재생된다.
- `prefers-reduced-motion`이 설정된 환경에서는 애니메이션 없이 즉시 전환된다.
- 다음 카드로 넘어가면 항상 앞면부터 다시 보여준다.
- 암기 완료된 카드에는 "완료" 배지를 표시한다.
- 애니메이션 진행 중의 연속 클릭은 무시하여 상태가 꼬이지 않게 한다.
- 긴 단어·뜻은 글자 크기를 줄이고 줄바꿈하여 카드 밖으로 넘치지 않게 한다.
- 카드는 `button` 요소로 구현하여 키보드 Enter/Space로도 뒤집을 수 있다.

### F2. 다음 카드
- "다음" 버튼을 누르면 다음 단어로 이동한다.
- 마지막 카드에서 "다음"을 누르면 첫 카드로 순환하고, "한 바퀴를 다 봤어요" 안내를 짧게 1회 보여준다.
- 단어가 1개뿐이면 같은 카드를 유지하되 앞면으로 되돌린다.

### F3. 암기 완료 토글
- 카드 아래 "암기 완료" 버튼을 누르면 완료 처리되고, 다시 누르면 해제된다.
- 변경 사항은 즉시 저장된다.

### F4. 단어 추가·목록
- 영단어·뜻 두 칸 모두 필수이며, 입력값의 앞뒤 공백은 제거한다.
- 하나라도 비어 있으면 추가 버튼이 비활성화되거나 "영단어와 뜻을 모두 입력해 주세요" 안내를 보여준다.
- 영단어 최대 100자, 뜻 최대 200자로 제한한다.
- Enter 키로도 추가할 수 있고, 추가 후에는 영단어 입력란에 자동으로 포커스가 이동한다.
- 추가한 단어는 즉시 목록과 카드 순환에 포함된다.
- 저장된 데이터가 없는 첫 실행 시, 중급 수준 영단어 10개(뜻 포함)를 샘플로 넣어 바로 체험할 수 있게 한다.

### F5. 저장·복원 (localStorage)
- 키 `vocabCards.v1` 하나에 전체 상태를 JSON으로 저장한다.
- 단어 추가, 완료 상태 변경, 현재 카드 이동 등 상태가 바뀔 때마다 즉시 저장한다.
- 페이지 로드 시 단어 목록, 완료 상태, 마지막으로 보던 카드를 복원한다(복원 직후 카드는 항상 앞면).

## 8. 데이터 모델

```
Word
- id: string            (crypto.randomUUID, 미지원 시 타임스탬프+난수로 대체)
- term: string           (영단어)
- meaning: string         (뜻)
- memorized: boolean      (기본 false)
- createdAt: string        (ISO 8601)
- updatedAt: string        (ISO 8601)

AppState
- version: number         (현재 1)
- words: Word[]           (추가된 순서 유지)
- filter: "all" | "unmemorized"  (1단계는 "all" 고정, 필드만 미리 정의)
- currentWordId: string | null   (인덱스가 아닌 ID로 현재 위치 저장)
```

현재 위치는 배열 인덱스가 아니라 `currentWordId`로 저장한다. 저장된 ID가 없거나 목록에서 찾을 수 없으면 첫 번째 카드를 기준으로 삼는다.

## 9. 예외 처리

| 상황 | 동작 |
|---|---|
| 단어 0개 | 카드 대신 "외울 단어를 추가해 보세요" 안내와 "단어 추가" 버튼을 보여주고, "다음"·"암기 완료" 버튼은 비활성화한다. |
| `localStorage` 사용 불가(시크릿 모드·차단 등) | 메모리에서만 동작하고 "이 브라우저에서는 저장되지 않아요" 배너를 표시한다. |
| 저장 데이터 JSON 파싱 실패·구조 불일치 | 원본 데이터를 `vocabCards.v1.backup` 키로 옮기고 샘플 데이터로 다시 시작하며, 안내 메시지를 보여준다. |

## 10. 비기능 요구사항

- 360px 모바일 폭부터 데스크톱까지 반응형으로 동작한다.
- 모바일에서는 조작 버튼을 화면 하단에 배치하고, 터치 영역은 44×44px 이상으로 하며, "다음" 버튼을 가장 크게 둔다.
- 카드는 `button` 요소로 구현해 Enter/Space로 뒤집을 수 있어야 하며, 앞/뒤 상태를 `aria-pressed` 또는 `aria-live`로 전달한다.
- 명도 대비 4.5:1 이상을 유지한다.
- 저장/로드, 상태 변경, 렌더링 로직을 함수 단위로 분리하여 다음 단계에서 기능을 추가하기 쉽게 한다.

| 2 | 뒷면 상태에서 "다음" → 다음 단어가 앞면으로 표시, 마지막 카드에서 "다음" → "1 / n"으로 순환 | ✅ 통과 |

### 개발 중 발견·수정한 이슈

- `.screen`, `.empty-state`, `.card-area`에 지정한 `display: flex`가 `hidden` 속성의 기본 스타일보다 CSS 우선순위가 높아, 화면/상태가 겹쳐 보이는 문제가 있었다. → `[hidden] { display: none !important; }` 규칙을 추가해 해결.
- `.card-inner`가 `<span>` 요소라 `display` 지정 없이 인라인으로 남아 카드가 찌그러져 보이는 문제가 있었다. → `.card-inner`에 `display: block`을 추가해 해결.

## 12. 다음 단계로의 연결

- `AppState.filter` 필드는 이미 정의되어 있으나 1단계에서는 `"all"`로 고정되어 있다. 2단계에서 "암기 전만 보기" 등 필터 UI/로직을 추가할 때 이 필드를 사용한다.
- `app.js`는 상태, 저장/복원, 렌더링, 동작(flip/next/toggle/add)이 함수 단위로 분리되어 있어, 단어 삭제·수정, 통계, 복습 주기 등 추후 기능을 이 구조 위에 얹을 수 있다.
