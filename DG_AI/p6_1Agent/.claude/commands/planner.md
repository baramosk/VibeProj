사용자가 입력한 기능/프로젝트 설명:

$ARGUMENTS

위 내용을 바탕으로 다음 순서로 작업하세요. 모든 결과물은 한국어로 작성합니다.

## 1. 입력 확인
- 설명이 비어 있으면 (`$ARGUMENTS`가 빈 값이면) 무엇을 만들지 한 번 물어보고 중단합니다.
- 설명이 있으면 바로 진행합니다.

## 2. 요구 사항 분석 (planner 에이전트 위임)
- `planner` 에이전트를 호출하여 입력된 설명을 요구 사항 정의서로 구체화하게 합니다.
- 에이전트에게 전달할 내용: 사용자 설명 원문, 현재 프로젝트 디렉터리 상태, 아래 3번과 4번 작업도 포함해 달라는 지시.
- 에이전트는 다음을 산출해야 합니다.
  - 배경, 목표, 성공 기준
  - 기능 요구 사항(FR)과 비기능 요구 사항(NFR)
  - MVP 범위와 제외 범위
  - 가정과 열린 질문(권장 답안 포함)

## 3. 설계
- 기술 스택, 주요 모듈, 데이터 흐름을 설계합니다.
- 기존 프로젝트 파일이 있으면 먼저 읽고, 이미 정해진 스택과 충돌하지 않게 맞춥니다.
- 설계 근거가 되는 대안이 여러 개면 장단점을 짧게 비교하고 추천안을 고릅니다.

## 4. 폴더 구조 설계
- 설계에 맞춰 디렉터리 트리를 제안합니다. 형식 예시:

```text
project-root/
├── src/          # 소스 코드
├── tests/        # 테스트
├── docs/         # 문서 (기획서 포함: docs/planning/)
└── ...
```

- 각 폴더와 주요 파일의 역할을 한 줄씩 설명합니다.
- 폴더 구조는 **설계 문서에 적기만 하고, 실제 폴더나 파일은 만들지 않습니다.** 사용자가 승인한 뒤에 생성합니다.

## 5. 결과 저장
- 기획서는 `docs/planning/YYYY-MM-DD-<주제-slug>.md`에 저장합니다.
- 문서에는 요구 사항, 설계, 폴더 구조 섹션을 모두 포함합니다.

## 6. 최종 응답
다음만 간결하게 보고합니다.
1. 저장한 기획서 경로
2. 핵심 요구 사항 요약 (5줄 이내)
3. 제안한 폴더 구조 트리
4. 사용자가 결정해야 할 열린 질문 (권장 답안 포함)
5. 다음 단계 제안 (예: 질문에 답하면 폴더 생성과 구현 계획 진행)
